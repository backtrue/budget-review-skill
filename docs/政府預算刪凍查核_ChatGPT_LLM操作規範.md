# 政府預算刪減／凍結查核操作規範

**Version 1.1 — Amount × Timing × Execution**

> 適用對象：ChatGPT、Claude、Gemini、其他 LLM、研究助理、新聞查核、政治議題資料整理  
> 目的：避免只看新聞標題、政黨說法或原始提案，建立可重複、可查證的政府預算判讀流程。

---

# 0. 任務原則

當使用者詢問「某預算被砍多少」「被凍多少」「為什麼被砍」「預算太晚通過會怎樣」「是否因此無法執行」「廠商是否不敢投標」「人才是否因此流失」「新聞說法是真是假」時，不得直接用新聞中的單一數字或單方敘事回答。

v1.1 必須依三個維度分析：

> **Amount（金額） × Timing（可用時間） × Execution（實際執行）**

完整流程：

**預算層級 → 歷史基準 → 基準年異常檢查 → 本年原編 → 最終三讀 → 刪減／凍結拆分 → 預算時間軸 → 最終理由 → 執行證據 → 影響分級**

政治攻防只能放在事實整理之後。

---

# 1. 先確認問題的預算層級

政府預算可能同時存在：

1. 中央政府總預算
2. 某部會／機關總預算
3. 某業務計畫
4. 某分支計畫
5. 某用途別科目
6. 特別預算
7. 追加預算

## 硬性規則

不同層級不得直接混算。

若新聞寫「某部會遭刪 90%」，必須確認 90% 指的是：

- 整個部會？
- 某個計畫？
- 某一筆宣傳費？
- 某個科目？

---

# 2. 建立金額基準：至少四個數字

至少查出：

| 基準 | 定義 |
|---|---|
| 去年法定預算 | 去年度最終法定預算 |
| 去年實際執行／決算 | 去年度實際支用金額 |
| 今年原編預算 | 行政機關送出的本年度預算 |
| 今年法定預算 | 本年度三讀後最終法定預算 |

但「去年」只能先當起點，不能自動視為正常基準年。

---

# 3. 先檢查「去年是不是異常年」

在用去年比較今年以前，必須檢查去年是否存在：

- 追加預算
- 大額凍結後解凍
- 預算延遲通過
- 一次性大型政策／工程／採購
- 天災、疫情、戰爭或其他特殊支出
- 組織改制
- 科目移轉或重分類
- 年度中政策大幅調整

如果存在，必須：

1. 往前看至少 2–3 年
2. 將去年拆成「年初可用」「年中追加／解凍」「年底最終總額」
3. 不得只拿去年年度最終總額與今年年度最終總額比較

## 為什麼？

相同的年度總額，如果取得時間不同，執行難度可能完全不同。

---

# 4. 刪除與凍結必須拆開

永遠分成兩個欄位。

## 刪減

代表法定預算直接減少。

```text
刪減率 = 刪減金額 ÷ 今年原編預算
```

## 凍結

代表經費仍存在，但暫時不得動支或受條件限制。

```text
凍結率 = 凍結金額 ÷ 今年原編預算
```

## 禁止

不得：

> 刪 10% + 凍 30% =「總共被砍 40%」

正確表達：

> 刪減 10%，另有 30% 遭凍結。

---

# 5. 凍結一定要查「怎麼解、何時解」

凍結金額本身不足以判斷影響。

至少確認：

- 是否提出書面報告即可
- 是否需專案報告
- 是否需到委員會報告
- 是否須經同意後始得動支
- 是否有指定改善事項
- 何時提出解凍
- 何時完成解凍
- 解凍後何時實際可動支

可粗分：

| 類型 | 說明 |
|---|---|
| 低門檻 | 書面程序即可解凍 |
| 中門檻 | 需專案報告／審查 |
| 高門檻 | 需取得同意後才能動支 |
| 未知 | 目前資料不足 |

注意：同樣凍結 30%，1 月解凍與 10 月解凍的實際執行效果完全不同。

---

# 6. 只用「最終通過版本」回答實際刪凍結果

## 可以用來判斷最終結果的資料

優先：

1. 三讀通過的法定預算
2. 預算審查總報告
3. 朝野協商結論
4. 最終決議
5. 追加預算
6. 解凍案或後續正式文件

## 不能直接當最終結果的資料

- 個別立委原始提案
- 黨團提案
- 委員會審議前版本
- 新聞報導「某委員擬砍」
- 政黨記者會
- Facebook／Threads／X 貼文

標準寫法：

> 原始提案曾要求刪減 X 元，但該數字不是最終結果。三讀後實際刪減為 Y 元，另凍結 Z 元。

---

# 7. 「為什麼刪凍」只看最後採納理由

若要回答「刪凍理由」，必須查：

- 最終決議文字
- 審查總報告
- 朝野協商結論
- 後續解凍文件引用的原決議

不得把某委員最初提案理由直接改寫成「立法院因為這個理由刪除預算」。

如果正式決議沒有寫清楚，應明確回答：

> 目前正式文件未載明足以確認的最終理由。

---

# 8. 百分比一定寫出分母

任何百分比都要回答：

> **占誰的多少？**

建議同時計算：

1. 占該科目／計畫原編比例
2. 占整個機關總預算比例

例如：

- 某計畫原編 1 億，刪 8,000 萬 → 該計畫刪 80%
- 該機關總預算 100 億 → 對機關總預算只占 0.8%

兩句可以同時成立，但政策意義完全不同。

---

# 9. 建立「預算時間軸」

這是 v1.1 的必要規則。

只要出現以下任一情況，就必須建立時間軸：

- 預算延遲通過
- 追加預算
- 凍結與解凍
- 分配／核定較晚
- 年中政策調整
- 保留款或跨年度執行

## 最低時間軸格式

| 時點 | 預算事件 | 金額／狀態 | 依據 | 實際意義 |
|---|---|---:|---|---|
| 年度開始 |  |  |  |  |
| 預算通過／公布 |  |  |  |  |
| 延遲期間 | 可動支規則 |  | 法律／正式規範 |  |
| 追加／解凍 |  |  |  |  |
| 分配／核定 |  |  |  |  |
| 實際可用 |  |  |  |  |
| 年底 | 剩餘執行時間 |  |  |  |

## 禁止

不得只用「年度最後預算總額」假設兩年執行條件相同。

---

# 10. 預算延遲通過時，不得直接寫「照去年預算花」

這種口語說法可能把不同支出類型與法定限制混在一起。

LLM 必須查：

1. 當地法律在預算未完成審議時如何規定
2. 當年度是否有特別執行規範
3. 既有計畫與新增計畫是否不同
4. 法定義務支出是否不同
5. 資本支出／採購是否受到不同限制

若分析台灣中央政府案件，應回到《預算法》及當年度正式執行規範核對，不得憑印象自行概括。

---

# 11. 判斷「刪的是什麼」

至少標記科目性質：

- 法定義務支出
- 人事費
- 基本維運
- 既有政策
- 新增政策
- 一次性採購
- 工程／資本支出
- 補助
- 委辦
- 宣傳
- 預備性經費
- 其他

同樣刪 1 億元，刪尚未執行的一次性採購、既有公共服務、法定義務支出，實際影響完全不同。

---

# 12. 建立「影響因果鏈」

不得直接：

> 被刪 30%／預算晚通過 → 業務一定停擺

必須逐步回答：

1. 被影響的是哪個預算科目？
2. 這個科目支付什麼？
3. 經費何時真正可用？
4. 過去每年實際花多少？
5. 本年度工作量是否改變？
6. 剩餘預算能否維持核心業務？
7. 是否能合法調整其他科目？
8. 採購、人力、服務流程需要多少時間？
9. 現在是否已有可觀察結果？

---

# 13. 影響必須分成三種證據等級

這是 v1.1 的第二個核心新增規則。

## A. 已證實影響

有實際資料證明結果已發生，例如：

- 月／季執行率異常
- 決算下降
- 保留款增加
- 流標率增加
- 投標家數下降
- 決標延後
- 服務名額下降
- 工程延後
- 計畫取消
- 缺額率／離職率增加

## B. 具體風險

制度機制與時間壓力明確存在，但尚無足夠結果資料。

例如：

> 9 月才取得可用經費，而大型採購通常需要數月，因此執行期間被明顯壓縮。

這可以判定為「具體風險」，但不能直接改寫成「因此一定流標」。

## C. 利害關係人主張

例如：

- 機關表示業務會受影響
- 廠商表示不敢投標
- 公務員表示士氣受損
- 政黨表示人才會外流

如果沒有獨立資料支持，只能列為「主張」。

### 硬性規則

**B、C 不得寫成 A。**

---

# 14. 如何驗證「廠商不敢投標」

不能只引用廠商或機關說法。

應查：

- 同類採購案數量
- 每案投標家數
- 流標／廢標率
- 決標率
- 招標至決標所需天數
- 決標是否大量集中在年底
- 履約期是否明顯縮短
- 是否出現跨年度／保留增加

若缺乏可比較資料，結論只能是「目前有主張／存在風險，尚未證實」。

---

# 15. 如何驗證「年底突然不知道怎麼花」

應查：

- 月／季累計執行率
- 第四季支出占全年比例
- 決標是否集中 Q4
- 大額採購是否集中年底
- 保留數與保留原因
- 次年度是否出現大量跨年履約

「年中追加很多錢」本身不能直接證明「年底亂花錢」。

---

# 16. 如何驗證「人才外流」

應找：

- 缺額率
- 離職率
- 招聘成功率
- 招募時間
- 約聘／專案人員續約率
- 人力裁減
- 組織人力變化

沒有資料時，不得寫成已證實影響。

---

# 17. 資料來源排序

## 第一層：法律／法定／正式執行資料

- 法律
- 法定預算書
- 三讀資料
- 審查總報告
- 決議
- 追加預算
- 解凍文件
- 決算
- 分配預算
- 預算執行報告
- 政府採購資料
- 官方業務統計

用途：確立事實與實際結果。

## 第二層：行政機關官方說明

- 部會新聞稿
- 業務報告
- 解凍報告
- 專案報告

用途：了解執行機關的說明與資料。

## 第三層：其他利害關係人

- 立委
- 政黨
- 公務員
- 廠商
- 工會
- 相關團體

用途：還原立場與發現待查證影響。

## 第四層：新聞與社群

用途：發現爭議、取得線索、了解外界敘事。

### 原則

低順位來源不得覆蓋高順位正式文件；利害關係人陳述不得自動升格成已證實影響。

# 18. 建議資料蒐集順序

## A. 最終法定數字

搜尋：

- `[年度] [機關] 法定預算`
- `[年度] 總預算案 三讀 [機關]`
- `[機關] 預算書 [年度]`

## B. 最終決議

- `[年度] 預算 審查總報告 [機關]`
- `[機關] 凍結 決議 [年度]`
- `[機關] 刪減 決議 [年度]`

## C. 歷年決算與異常基準

- `[機關] 決算 [年度]`
- `[機關] 預算執行率 [年度]`
- `[年度] 追加預算 [機關]`
- `[機關] 解凍 [年度]`

## D. 預算時間軸

- 三讀／公布日期
- 追加預算通過日期
- 解凍日期
- 分配／核定日期
- 預算未通過期間的法定執行規則

## E. 執行影響

依爭議查：

- 政府電子採購網／採購統計
- 月／季執行報告
- 決算與保留
- 服務量統計
- 人力統計

## F. 最後才看新聞與政治說法

用來檢查：

- 是否把提案寫成通過
- 是否把凍結寫成刪除
- 是否選擇性使用分母
- 是否只比異常的去年
- 是否忽略預算可用時間
- 是否把風險或主張寫成已發生影響

# 19. 必做計算

```text
刪減率 = 刪減金額 / 今年原編預算

凍結率 = 凍結金額 / 今年原編預算

去年至今年法定預算變化率
= (今年法定預算 - 去年法定預算) / 去年法定預算

去年執行率
= 去年實際執行 / 去年法定預算

今年法定預算相對去年實際執行差額
= 今年法定預算 - 去年實際執行
```

若有追加預算：

```text
追加後總額 = 原法定預算 + 追加預算
```

但必須同時列出追加通過與可動支時點，不能只列最後總額。

所有比例必須註明分母。

# 22. 一句核心心法

> **預算不是只有 Amount；還要看 Timing，最後用 Execution 驗證。**

每次看到預算爭議，固定問：

> **相較於什麼？**  
> **什麼時候真正能用？**  
> **刪凍了哪裡？**  
> **最後為什麼？**  
> **最後真的發生了什麼？**

先把預算事實、時間與執行證據整理完，再決定政治論述是否成立。
