# 政府預算刪減／凍結查核操作規範

> 適用對象：ChatGPT、LLM、研究助理、新聞查核、政治議題資料整理  
> 目的：避免只看新聞標題、政黨說法或原始提案，建立可重複、可查證的政府預算判讀流程。

---

## 0. 任務原則

當使用者詢問「某預算被砍多少」「被凍多少」「為什麼被砍」「是否因此無法執行」「新聞說法是真的假的」時，不得直接用新聞中的單一數字回答。

必須先建立：

**歷史基準 → 本年原編 → 最終三讀 → 刪減／凍結拆分 → 最終理由 → 實際業務影響**

政治攻防只能放在事實整理之後。

---

# 1. 先確認問題的預算層級

政府預算可能同時存在以下不同層級：

1. 中央政府總預算
2. 某部會／機關總預算
3. 某業務計畫
4. 某分支計畫
5. 某用途別科目
6. 特別預算

### 硬性規則

不同層級不得直接混算。

若新聞寫「某部會遭刪 90%」，必須確認 90% 指的是：

- 整個部會？
- 某個計畫？
- 某一筆宣傳費？
- 某個科目？

---

# 2. 建立四個基準數字

至少查出：

| 基準 | 定義 |
|---|---|
| 去年法定預算 | 去年度三讀後可用預算 |
| 去年實際執行／決算 | 去年度實際支用金額 |
| 今年原編預算 | 行政機關送出的本年度預算 |
| 今年法定預算 | 本年度三讀後最終預算 |

### 為什麼「去年實際執行」必要？

因為：

> 原編 10 億 → 三讀剩 8 億

不代表 8 億一定不夠。

若過去三年平均只執行 6.5 億，就還需回答：

- 本年度是否新增業務？
- 成本是否上升？
- 執行量是否增加？
- 去年低執行是否有特殊原因？

反之，若過去執行率接近 100%，今年突然減少 20–30%，實際影響的可能性更高。

---

# 3. 刪除與凍結必須拆開

永遠分成兩個欄位：

## 刪減

代表法定預算直接減少。

計算：

**刪減率 = 刪減金額 ÷ 今年原編預算**

## 凍結

代表經費仍存在，但暫時不得動支或受條件限制。

計算：

**凍結率 = 凍結金額 ÷ 今年原編預算**

### 禁止

不得：

> 刪 10% + 凍 30% =「總共被砍 40%」

正確表達：

> 刪減 10%，另有 30% 遭凍結。

---

# 4. 凍結一定要查「如何解凍」

凍結金額本身不足以判斷影響。

至少確認：

- 是否提出書面報告即可
- 是否須提出專案報告
- 是否須到委員會報告
- 是否須經同意後始得動支
- 是否有期限
- 是否有指定改善事項

可以標記為：

| 類型 | 說明 |
|---|---|
| 低門檻 | 書面程序即可解凍 |
| 中門檻 | 需專案報告／審查 |
| 高門檻 | 需取得同意才能動支 |
| 未知 | 目前資料不足 |

這只是對執行程序的描述，不代表價值判斷。

---

# 5. 只用「最終三讀」回答實際刪凍結果

## 可以用來判斷最終結果的資料

優先：

1. 三讀通過的法定預算
2. 立法院預算審查總報告
3. 朝野協商結論
4. 最終決議
5. 解凍案或後續正式文件

## 不能直接當最終結果的資料

- 個別立委原始提案
- 黨團提案
- 委員會審議前版本
- 新聞報導「某委員擬砍」
- 政黨記者會
- Facebook／Threads／X 貼文

### 標準寫法

若使用者問到一個被大量報導的提案：

> 「原始提案曾要求刪減 X 元，但該數字不是最終結果。三讀後實際刪減為 Y 元，另凍結 Z 元。」

---

# 6. 「為什麼刪凍」只看最後採納理由

若要回答「刪凍理由」，必須查：

- 最終決議文字
- 審查總報告
- 朝野協商結論
- 後續解凍文件引用的原決議

### 禁止

不得把：

> 某委員原提案寫的理由

直接改寫成：

> 「立法院因為這個理由刪除預算。」

除非該理由最後真的出現在通過的決議中。

---

# 7. 百分比一定寫出分母

任何百分比都要回答：

> **占誰的多少？**

建議同時算兩個比例：

1. 占該科目／計畫原編比例
2. 占整個機關總預算比例

例如：

- 某計畫原編 1 億，刪 8,000 萬 → 該計畫刪 80%
- 該機關總預算 100 億 → 對機關總預算只占 0.8%

兩句都成立，但代表的政策意義不同。

---

# 8. 判斷「刪的是什麼」

至少標記科目性質：

- 法定義務支出
- 人事費
- 基本維運
- 既有政策
- 新增政策
- 一次性採購
- 工程／資本支出
- 補助
- 委辦
- 宣傳
- 預備性經費
- 其他

同樣刪 1 億元：

- 刪一筆尚未執行的一次性採購
- 刪一筆已進行中的公共服務
- 刪法定義務支出

意義完全不同。

---

# 9. 建立「影響因果鏈」

不得直接：

> 被刪 30% → 業務一定停擺

必須逐步回答：

1. 被刪的是哪個預算科目？
2. 這個科目實際支付什麼？
3. 過去每年實際花多少？
4. 本年度工作量有沒有增加？
5. 剩餘預算能否維持核心業務？
6. 是否能從其他合法科目調整？
7. 凍結能否在年度內解開？
8. 最終能指出哪一項服務受到什麼影響？

可接受的影響描述例如：

- 服務據點減少 X 處
- 補助人數可能少 X 人
- 採購數量由 X 降到 Y
- 活動場次由 X 降到 Y
- 工程時程延後
- 原計畫取消

如果只能找到「機關表示恐受影響」，應寫成：

> 「機關主張將造成影響，目前尚缺少可量化的執行資料證明影響規模。」

---

# 10. 資料來源排序

資料來源可信度與用途分開處理。

## 第一層：法定／正式文件

- 法定預算書
- 立法院三讀資料
- 審查總報告
- 決議
- 決算
- 預算執行報告

用途：確立事實。

## 第二層：行政機關官方資料

- 部會新聞稿
- 業務報告
- 解凍報告

用途：了解行政機關主張與執行資訊。

## 第三層：政治行為者資料

- 立委說明
- 政黨記者會
- 黨團新聞稿

用途：還原政治立場與提案理由。

## 第四層：新聞與社群

用途：發現爭議、取得線索、確認外界如何描述。

### 原則

低層級來源不得覆蓋高層級正式文件。

---

# 11. 建議資料蒐集順序

進行網路查核時，依序搜尋：

### A. 最終法定數字

搜尋：
- `[年度] [機關] 法定預算`
- `[年度] 總預算案 三讀 [機關]`
- `[機關] 預算書 [年度]`

### B. 最終決議

搜尋：
- `[年度] 預算 審查總報告 [機關]`
- `[機關] 凍結 決議 [年度]`
- `[機關] 刪減 決議 [年度]`

### C. 去年執行／決算

搜尋：
- `[機關] 決算 [年度]`
- `[機關] 預算執行率 [年度]`
- `[機關] 決算書`

### D. 解凍條件

搜尋：
- `[機關] 解凍案`
- `[預算科目] 凍結 書面報告`
- `[預算科目] 凍結 專案報告`

### E. 最後才看新聞與政治說法

用來比對：

- 新聞有沒有把提案寫成通過
- 有沒有把凍結寫成刪除
- 有沒有刻意選擇分母
- 有沒有跳過去年執行額

---

# 12. 必做計算

對每個爭議科目至少計算：

```text
刪減率 = 刪減金額 / 今年原編預算

凍結率 = 凍結金額 / 今年原編預算

去年至今年法定預算變化率
= (今年法定預算 - 去年法定預算) / 去年法定預算

去年執行率
= 去年實際執行 / 去年法定預算

今年法定預算相對去年實際執行差額
= 今年法定預算 - 去年實際執行
```

所有比例都必須註明分母。

## 實際影響

依照：

> 科目 → 計畫 → 歷年執行 → 本年工作量 → 剩餘經費 → 可量化影響

## 審議過程（必要時才列）

如果使用者想知道政治攻防，再另外整理：

- 誰提了什麼
- 原始提案是多少
- 中間如何協商
- 最後改成什麼

並在標題或第一句明確寫：

> 「以下是審議過程，不是最終通過結果。」

# 14. LLM 自我檢查 Checklist

回答前逐項確認：

- [ ] 我有確認討論的是哪一層級預算
- [ ] 我有去年法定預算
- [ ] 我有嘗試取得去年實際執行／決算
- [ ] 我有今年原編預算
- [ ] 我有今年三讀後法定預算
- [ ] 我把刪減與凍結分開
- [ ] 我沒有把刪減與凍結相加稱作「被砍」
- [ ] 所有百分比都有清楚分母
- [ ] 我查的是最終通過版本，不是只有原始提案
- [ ] 刪凍理由來自最終決議，而非單一提案人說法
- [ ] 有凍結時，我查了解凍條件
- [ ] 我有辨認被刪凍的是哪一類科目
- [ ] 我有用歷年實際執行檢查「會不會真的不夠」
- [ ] 我沒有從刪減比例直接跳到服務停擺
- [ ] 若資料不足，我有明確標示不足而不是猜測
- [ ] 我把政府、政黨、立委、新聞的說法視為主張，而不是自動當成事實

---

# 15. 一句核心心法

> **不要只問「砍了多少」，要問：相較於什麼、刪凍了哪裡、最後為什麼刪凍、以及最後真的少了什麼。**

更高一層的原則是：

> **先把預算事實整理完，再決定政治論述是否成立。**
