# 政府預算刪減／凍結查核操作規範

**Version 1.3 — Official Source Routing + Amount × Timing × Dependency × Execution**

> 適用對象：ChatGPT、Claude、Gemini、其他 LLM、研究助理、新聞查核與政治議題資料整理。

---

# 0. 任務原則

當使用者詢問：

- 某預算被砍多少
- 被凍多少
- 為什麼被刪凍
- 預算太晚通過是否影響執行
- 某個只占 5% 的科目被刪是否會卡住整體
- 廠商是否不敢投標
- 人才是否因此流失
- 新聞或政治說法是真是假

不得直接使用新聞中的單一數字或單方敘事作答。

v1.3 的完整流程是：

> **Official Source Routing → Amount → Timing → Dependency → Execution → 影響分級 → 政治判讀**

---

# 1. 先定義問題層級

確認使用者討論的是：

1. 中央政府總預算
2. 特定部會／機關
3. 業務計畫
4. 分支計畫
5. 用途別科目
6. 特別預算
7. 地方政府預算

不同層級不得混算。

若新聞寫「某部會被刪 80%」，必須先確認 80% 指的是整個部會、某個計畫或單一科目。

---

# 2. Official Source Routing

任何查核開始前，先列出待查事實與其 Source of Record。

## 2.1 行政院原編／預算版本

優先：

- 行政院主計總處中央政府總預算及附屬單位預算
- 各機關正式單位預算案
- 立法院預決算知識庫作歷史索引與交叉核對

## 2.2 最終刪減、凍結、決議理由

優先：

- 立法院最終院會資料
- 預算審查總報告
- 最終決議
- 朝野協商紀錄
- 後續解凍正式文件

不得以行政機關原始預算書取代立法院最終決議。

## 2.3 實際執行／決算

優先：

- 各機關會計報表
- 各機關決算
- 中央政府總決算
- 審計部總決算審核報告

## 2.4 採購影響

優先：政府電子採購網。

## 2.5 地方政府

先從主計總處地方預決算平台找到該縣市正式預算與決算網站，再視問題需要查地方議會文件。

## 2.6 物價

依科目選擇適當指數，不得一律套 CPI。

完整路由見 [`官方資料來源路由.md`](./官方資料來源路由.md)。

---

# 3. 資料新鮮度與版本

每份資料必須確認：

- 年度
- 發布／更新日期
- 預算案或法定預算
- 三讀前或三讀後
- 是否有追加減
- 是否有後續解凍

官方來源更新速度可能不同。

若主計總處尚未更新最新法定預算，但立法院已有三讀正式文件，而問題是「最新三讀結果」，應使用立法院正式文件，並註明主計總處彙整頁尚未更新。

硬性規則：

> **Source of Record 取決於問題類型、程序階段與更新時點。**

---

# 4. 建立歷史基準

至少查：

| 基準 | 定義 |
|---|---|
| 前 2–3 年法定預算 | 避免單一年異常 |
| 前 2–3 年實際執行／決算 | 真正支出基準 |
| 今年原編 | 行政機關原始需求 |
| 今年法定預算 | 三讀後最終法定額度 |

## 4.1 去年不是自動正常基準

若去年有：

- 追加／減預算
- 大額凍結後解凍
- 預算延遲通過
- 一次性大型支出
- 災害／特殊政策
- 組織改制
- 科目重分類

應標記「異常基準年」，往前看 2–3 年並拆開時序。

---

# 5. Amount｜金額分析

固定計算：

```text
刪減率 = 刪減金額 / 今年原編預算

凍結率 = 凍結金額 / 今年原編預算

法定預算年增減率
= (今年法定預算 - 去年法定預算) / 去年法定預算

去年執行率
= 去年實際執行 / 去年法定預算

今年法定預算相對去年執行差額
= 今年法定預算 - 去年實際執行
```

所有百分比都必須寫分母。

不得把刪減與凍結合併成單一「被砍率」。

---

# 6. 刪減與凍結完全拆開

## 刪減

代表法定預算直接減少。

## 凍結

代表經費仍存在，但動支受條件限制。

有凍結時一定查：

- 解凍條件
- 書面報告／專案報告
- 是否需經同意
- 解凍日期
- 解凍後剩餘執行時間

可粗分：

| 類型 | 說明 |
|---|---|
| 低門檻 | 書面程序即可 |
| 中門檻 | 專案報告／審查 |
| 高門檻 | 需取得同意始得動支 |
| 未知 | 尚未取得正式資料 |

---

# 7. 提案不等於通過

不得以：

- 個別立委原始提案
- 黨團提案
- 委員會審議前版本
- 新聞中的擬刪金額
- 社群貼文

描述最終預算結果。

正確寫法：

> 原始提案曾要求刪減 X 元；最後三讀實際刪減 Y 元，另凍結 Z 元。

若要說「為什麼刪」，理由應來自最後正式決議，而不是提案人最初寫的理由。

---

# 8. Timing｜預算時間軸

若案件有以下任一情況，必須建立年度時間軸：

- 預算延遲通過
- 追加／減預算
- 大額凍結／解凍
- 晚核定
- 分配預算時點明顯異常

至少整理：

| 日期／期間 | 事件 | 當時可動支狀態 |
|---|---|---|
| 年度開始 |  |  |
| 預算三讀／公布 |  |  |
| 追加減 |  |  |
| 解凍 |  |  |
| 分配／核定 |  |  |

不得把「年度最終預算相同」推論成「執行條件相同」。

不得把預算未完成審議簡化成「照去年預算花」，應查當年度法律與正式執行規則。

---

# 9. Dependency｜關鍵依賴分析

當被刪科目占比小，但被主張會影響整體計畫時，必須分析：

1. 該科目產出是什麼？
2. 哪些下游工作依賴它？
3. 依賴是法律、契約、技術或行政？
4. 有無替代方案？
5. 有無其他合法財源？
6. 是否已有既有設備、庫存或跨年度資源？
7. 沒有它，下游是否真的不能繼續？

分類：

| 類型 | 定義 |
|---|---|
| 獨立項目 | 主要只影響自身 |
| 部分依賴 | 降低下游效率／規模 |
| 關鍵前置項目 | 部分後續工作無法開始 |
| 單點失效項目 | 金額雖小但核心功能可能整體失效 |
| 未能確認 | 尚無證據建立依賴鏈 |

不得說：

> 只占 5%，所以影響只有 5%。

也不得說：

> 這 5% 很關鍵，所以一定全案癱瘓。

兩邊都需要證據。

---

# 10. Execution｜實際執行驗證

不得從 Amount／Timing／Dependency 直接跳到結果。

必須尋找實際執行證據，例如：

- 月／季累計執行率
- 實現數
- 決算
- 保留款
- 招標／決標／流標
- 服務據點／服務量
- 補助人數
- 採購數量
- 工程進度
- 計畫取消／延期
- 缺額、離職、招聘、續約

---

# 11. 常見論述的證據要求

## 「廠商不敢投標」

查：

- 投標家數
- 流標率
- 重複招標
- 決標率
- 決標時間
- 履約期

主要來源：政府電子採購網。

## 「年底突然拿到錢不知道怎麼花」

查：

- 月／季執行率
- Q4 支出集中度
- Q4 招標／決標集中度
- 保留款
- 實際成果

## 「人才外流」

查：

- 離職率
- 缺額率
- 招聘
- 約聘續約
- 正式人力異動資料

若查不到，不能把它寫成已證實影響。

---

# 12. 通膨與實質價格

不得機械式用 CPI 調整所有預算。

應依支出性質：

| 支出 | 優先考量 |
|---|---|
| 一般消費性支出 | CPI 或對應指數 |
| 工程 | CCI／材料／勞務細項 |
| 進口設備 | 匯率、進口物價、設備市場價 |
| 人事 | 法定調薪、員額、薪資制度 |
| 補助 | 補助單價、受益人數、服務量 |

只有指數與支出內容有實質關聯，才能做實質價格調整。

---

# 13. 影響證據三級

## Level 1：已證實影響

已有正式或可量化資料證明結果發生。

## Level 2：具體風險

制度機制、時間壓力或依賴關係已成立，但結果尚未被充分證實。

## Level 3：利害關係人主張

政府、政黨、公務員、廠商、媒體或社群提出，尚未獨立驗證。

硬性規則：

> **不得把 Level 2 或 Level 3 寫成 Level 1。**

---

# 14. 官方來源路由表

| 問題 | Primary Source | Cross-check |
|---|---|---|
| 今年原編多少 | 主計總處／機關預算案 | 立法院預決算知識庫 |
| 最終法定多少 | 主計總處法定預算／立法院法定資料 | 雙方交叉核對 |
| 最後刪多少／凍多少 | 立法院最終審查／院會決議 | PPG 協商紀錄 |
| 最終理由 | 最終決議文字 | 審查總報告 |
| 去年實際花多少 | 機關決算／中央政府總決算 | 審計部 |
| 月度執行情況 | 機關會計報表 | 主計執行資料 |
| 追加減 | 主計總處＋立法院預決算知識庫 | 法定文件 |
| 地方政府 | 主計總處地方平台 → 地方政府官網 | 地方議會 |
| 採購影響 | 政府電子採購網 | 機關採購資料 |
| 工程成本 | CCI | 材料／勞務細項 |

# 15. 標準輸出模板

## A. 結論

先回答：

- 流傳說法是否精確
- 實際刪減／凍結
- 是否存在時間或依賴問題
- 影響證據層級

## B. Source Routing

| 待查事實 | Source of Record | 文件版本／日期 | 是否取得 |
|---|---|---|---|
| 原編 | | | |
| 最終刪凍 | | | |
| 決算 | | | |
| 執行 | | | |

## C. Amount

列出 2–3 年法定預算、決算、本年原編、法定、刪減、凍結與追加減。

## D. Timing

列出關鍵日期與可動支狀態。

## E. Dependency

列出依賴鏈、替代方案與分類。

## F. Execution

列出實際結果與證據層級。

## G. 審議過程（必要時）

原始提案與最終結果完全分開。

# 17. 一句核心心法

> **先找對資料，再算對數字；先證明依賴，再判斷影響。**
