# 政府預算刪減／凍結查核操作規範

**Version 1.4 — Official Source Routing + Amount × Timing × Dependency × Use-of-Funds × Execution**

> 適用對象：ChatGPT、Claude、Gemini、其他 LLM、研究助理、新聞查核、政治議題資料整理  
> 目的：避免只看新聞標題、政黨說法、原始提案、單一比例或預算用途描述，建立可重複、可查證的政府預算判讀流程。

---

# 0. 任務原則

遇到以下問題時使用本規範：

- 某預算被砍／被凍多少
- 為什麼被刪凍
- 預算太晚通過會怎樣
- 某個只占 5% 的科目被刪是否會卡住整體
- 某服務是否因此無法執行
- 廠商是否不敢投標
- 人才是否因此流失
- **某筆預算歷年花費方向／用途／流向**
- 某基金補助、委辦或採購主要花在哪
- 新聞或政治說法是真是假

完整流程：

> **Official Source Routing → Amount → Timing → Dependency → Use-of-Funds（適用時）→ Execution → Political Judgment**

政治價值判斷只能放在事實整理之後。

---

# 1. Official Source Routing

先回答：

1. 我要證明哪個事實？
2. 它屬於哪個程序階段？
3. 哪個官方機關是該事實的 Source of Record？
4. 該資料是否已更新到最新程序？

## 常見路由

| 問題 | Primary Source |
|---|---|
| 行政院原編多少 | 主計總處／機關預算案 |
| 最終刪多少、凍多少 | 立法院最終院會、審查總報告、決議 |
| 最終刪凍理由 | 立法院最終決議、協商、審查總報告 |
| 去年／歷年實際花多少 | 單位決算、總決算、會計報表 |
| 某月／某季執行多少 | 機關會計報表 |
| 採購是否流標、何時決標 | 政府電子採購網 |
| 依法可以花在哪 | 法規、作業要點、預算用途說明 |
| 實際花去哪 | 決算、會計、採購、補助／受款、審計、正式支用報告 |
| 地方政府預決算 | 主計總處地方預決算平台 → 各地方正式網站 |

硬性規則：

> **官方來源不是單一排行榜。Source of Record 取決於問題類型、程序階段與更新時點。**

完整路由見：[`官方資料來源路由.md`](./官方資料來源路由.md)

---

# 2. Amount｜建立金額基準

至少查：

- 前 2–3 年法定預算
- 前 2–3 年實際執行／決算
- 今年原編
- 今年三讀後法定預算
- 刪減
- 凍結
- 追加／減預算
- 必要時的特別預算、第二預備金、保留款等

## 必做計算

```text
刪減率 = 刪減金額 / 今年原編預算
凍結率 = 凍結金額 / 今年原編預算
去年執行率 = 去年實際執行 / 去年法定預算
今年法定相對去年決算差額 = 今年法定預算 - 去年實際執行
```

所有比例都必須說明分母。

禁止：

> 刪 10% + 凍 30% =「被砍 40%」

---

# 3. 歷史基準：不要只拿去年

若去年存在以下情況，視為可能異常基準年：

- 追加／減預算
- 大額凍結後解凍
- 預算延遲通過
- 一次性大型支出
- 災害或特殊政策
- 組織改制
- 科目重分類

此時往前比較至少 2–3 年。

若用途分類跨年有拆分、合併、改名、移轉，先建立 crosswalk，再做趨勢比較。

---

# 4. 刪減與凍結完全分開

## 刪減

代表法定預算直接減少。

## 凍結

代表經費仍存在，但動支受限制。

有凍結時查：

- 解凍條件
- 書面報告／專案報告／需同意後始得動支
- 解凍日期
- 解凍後剩餘執行時間

不得把凍結描述成「完全沒影響」，也不得直接當成刪除。

---

# 5. 提案不等於通過

以下只能描述審議過程：

- 個別立委原始提案
- 黨團提案
- 委員會審議前版本
- 新聞中的「擬刪」
- 社群貼文

最終結果優先查：

1. 立法院最終院會
2. 審查總報告
3. 最終決議
4. 朝野協商紀錄
5. 後續解凍正式文件

若問「為什麼刪凍」，理由以最後採納的正式決議為準。

---

# 6. Timing｜建立預算時間軸

若涉及延遲、追加、凍結、解凍或晚核定，整理：

- 年度開始
- 預算案提出
- 三讀／公布
- 預算尚未完成時的法定執行依據
- 追加／減預算通過時間
- 凍結／解凍時間
- 分配／核定／可動支時間
- 年度剩餘可執行期間

硬性規則：

> **年度最後總額相同，不等於全年執行條件相同。**

> **不得把預算延遲通過簡化成「照去年預算花」。**

---

# 7. Dependency｜關鍵依賴分析

若某科目占比小，但被主張為整體必要前置，固定查：

1. 該科目具體產出
2. 哪些下游依賴它
3. 依賴是法律／契約／技術／行政哪一類
4. 替代方案
5. 其他合法財源或既有資源
6. 沒有它，下游是否真的無法繼續

分類：

- 獨立項目
- 部分依賴
- 關鍵前置項目
- 單點失效項目
- 未能確認

硬性規則：

> **「只占 5%」不能推出「影響只有 5%」；「這 5% 很關鍵」也不能推出「全案一定癱瘓」。**

詳細方法見：[`關鍵依賴分析.md`](./關鍵依賴分析.md)

---

# 8. Use-of-Funds｜支出用途分析

當使用者問：

- 歷年花費方向
- 主要用途
- 錢花去哪
- 補助對象
- 委辦流向
- 採購內容

必須啟動此模組。

## 8.1 四層資料必須分開

### Budgeted Purpose

法規、作業要點、預算書、計畫用途說明。

只能證明「可以／預計花在哪」。

### Reported Use

業務報告、解凍報告、專案報告、年報、官方支用彙整。

是機關正式揭露的實際用途，但若沒有分類金額，不得推算占比。

### Actual Expenditure

決算、會計報表、採購決標、補助／受款公開資料、審計報告、依法公開逐筆資料。

只有依此層資料，才能在公開粒度允許時回答實際金額、類別、對象或標案。

### Public Disclosure Level

每年度標記：

- L1：逐筆
- L2：分類金額
- L3：主要用途／部分案例
- L4：只有總額
- L5：未公開／依法受限制

硬性規則：

> **預算允許用途 ≠ 機關宣稱用途 ≠ 實際支出用途 ≠ 公開逐筆明細。**

## 8.2 歷年用途比較

每年建立：

| 年度 | 法定預算 | 決算 | 可確認用途 | 證據類型 | 公開粒度 |
|---|---:|---:|---|---|---|
| | | | | Budgeted / Reported / Actual | L1–L5 |

只有取得分類金額時，才能計算實際用途占比：

```text
用途實際支出占比 = 該用途實際支出 / 該年度實際支出總額
```

如果只有預算配置，只能稱為「預算配置占比」。

## 8.3 機密／受限制資料

必須區分：

- 法定監督機關可以查核
- 一般公眾可以取得逐筆明細

兩者不是同一件事。

若公開資料不足，標準寫法：

> 「目前可確認年度總額與公開揭露的主要用途，但公開資料不足以完整重建每筆支出；未公開部分無法推定為任何特定用途。」

詳細方法見：[`支出用途分析.md`](./支出用途分析.md)

---

# 9. Execution｜驗證實際影響

查：

- 月／季執行率
- 累計實現數
- 決算
- 保留款
- 招標／決標／流標
- 服務量
- 補助人數
- 採購數量
- 工程時程
- 計畫取消／延期
- 缺額、離職、續約、招聘
- 下游依賴是否實際停擺

不得從預算數字直接跳到結果。

---

# 10. 影響證據分級

## Level 1：已證實影響

有實際執行、決算、採購、服務、人力或工程資料證明結果已發生。

## Level 2：具體風險

制度機制、時間壓力或依賴關係成立，但結果尚未有足夠資料。

## Level 3：利害關係人主張

政府、政黨、公務員、廠商、媒體或社群提出，但尚未獨立驗證。

> **不得把 Level 2 或 Level 3 寫成 Level 1。**

---

# 11. 通膨與實質成本

不得自動用 CPI 調整所有預算。

依支出內容選擇：

- 一般消費性支出 → CPI 或相關指數
- 工程 → CCI／材料／勞務指數
- 進口設備 → 匯率、進口物價、設備價格
- 人事 → 法定調薪、員額、薪資制度
- 補助 → 每人／每件補助基準與服務量

---

# 12. 標準工作流程

1. 定義問題與預算層級
2. Official Source Routing
3. 建立 2–3 年歷史基準
4. 核對本年度原編／三讀／法定／追加減／凍結解凍
5. 計算 Amount
6. 必要時建立 Timing
7. 必要時做 Dependency
8. 問用途時做 Use-of-Funds
9. 用 Execution 驗證實際結果
10. 對影響做證據分級
11. 最後才做政治判斷

---

# 13. 標準輸出

## 結論

先說清楚：

- 說法是否精確
- 資料版本
- 刪減／凍結（若適用）
- Timing／Dependency 是否存在
- 若問用途，公開資料能回答到哪個粒度
- 影響證據等級

## Source Routing

| 待查事實 | Primary Source | 版本／狀態 |
|---|---|---|

## 預算比較

| 指標 | 金額 | 說明 |
|---|---:|---|

## Timing（適用時）

列日期與真正可用時間。

## Dependency（適用時）

列依賴鏈、替代方案、關鍵性分類。

## Use-of-Funds（適用時）

| 年度 | 法定預算 | 決算 | 可確認用途 | 證據類型 | 公開粒度 |
|---|---:|---:|---|---|---|

## Execution

列實際結果與證據等級。

---

# 14. 禁止事項

- 禁止把提案寫成通過
- 禁止把刪減與凍結相加稱為被砍
- 禁止百分比不交代分母
- 禁止只拿異常的去年當唯一基準
- 禁止把年度總額等同全年可用
- 禁止把小占比直接等同小影響
- 禁止把「關鍵」直接等同全案癱瘓
- 禁止以新聞稿覆蓋更合適的正式 Source of Record
- 禁止把合理風險寫成已發生事實
- **禁止把 Budgeted Purpose 當成 Actual Expenditure**
- **禁止從少數用途案例推算整體占比**
- **禁止把採購網當成所有政府支出的完整流向**
- **禁止在資料未公開時自行補完機密／敏感明細**

# 一句核心心法

> **先找對資料，再算對數字；先分清「可以怎麼花」與「實際怎麼花」，再判斷依賴與影響。**
