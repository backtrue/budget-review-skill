# 政府預算刪凍查核 Skill

**Version 1.2 — Amount × Timing × Dependency × Execution**

一套給 ChatGPT、Claude、Gemini、Agent 與其他 LLM 使用的政府預算查核規則。

它的目的不是替任何政黨、政府或政治人物辯護，而是要求 AI 在討論「預算被砍」「預算被凍」「某政策做不下去」以前，先把真正的預算事實、可用時間、科目依賴與執行影響整理清楚。

> **不要只問「砍了多少」，還要問：這筆錢什麼時候能用、被刪的是不是其他預算的必要前置、以及最後真的發生了什麼。**

---

## v1.2 新增：Critical Dependency Analysis

預算占比小，不代表影響一定小。

假設一個計畫總預算 100 億，其中 A 科目只有 5 億，占 5%。如果 A 只是獨立活動，刪除 A 可能真的只影響 5%。

但如果 A 是：

- 必要授權
- 土地
- 電力
- 網路
- 認證
- 保險
- 核心設備
- 專業人力
- 前置工程
- 其他依法、依約或技術上必須先完成的條件

那麼 A 即使只占 5%，仍可能使其餘 95% 無法發揮作用。

因此 v1.2 新增 **Dependency（依賴關係）**：

> **Amount × Timing × Dependency × Execution**

### Amount｜到底有多少錢？

比較法定預算、原編、刪減、凍結、追加、決算與歷年基準。

### Timing｜這些錢什麼時候真的能用？

檢查三讀／公布時點、延遲期間的法定執行依據、追加預算、解凍日期、分配／核定時點，以及年度還剩多少執行時間。

### Dependency｜少掉這筆，其他預算還能不能發生作用？

確認被刪科目的具體產出、下游依賴、法律／契約／技術前置條件、替代方案與其他合法財源。

### Execution｜最後真的造成什麼影響？

繼續找月／季執行率、決標與流標、保留款、服務量、工程時程、補助人數、缺額、離職，以及下游計畫是否真的停止或延後。

## 為什麼需要這個 Skill？

每逢政府預算審查，新聞與社群常會出現：

- 「某預算被砍 XX 億」
- 「某項預算遭刪 80%」
- 「立委提案刪光某筆預算」
- 「才刪總預算 5%，根本沒影響」
- 「這筆小預算一刪，整個政策就完全不能做」
- 「某機關因為預算遭砍，所以業務做不下去」

這些句子可能有部分事實，但往往少了最重要的上下文。

真正需要先回答的是：

- 今年原本編多少？
- 去年法定預算是多少？
- 去年實際又花了多少？
- 去年是不是特殊基準年？
- 「刪減」與「凍結」各是多少？
- 凍結要怎麼解凍、什麼時候能用？
- 新聞講的是原始提案，還是最後三讀結果？
- 刪凍理由是提案人的理由，還是最後通過的決議文字？
- 所謂「刪 80%」的分母，是整個部會，還是某一個小科目？
- 被刪的小科目是不是其他計畫的必要前置？
- 有沒有替代方案或其他合法財源？
- 最後到底有哪一項服務、名額、採購、工程或時程真的受到影響？

這個 Skill 就是把這些問題固定化，避免 LLM 只跟著新聞標題、政治說法或單一比例走。

## 核心原則

### 1. 先建立合理的歷史基準

至少比較：

1. 歷年法定預算
2. 歷年實際執行／決算
3. 今年原編預算
4. 今年三讀後法定預算

如果去年有追加預算、重大解凍、延遲通過、一次性大型支出、組織改制或科目重分類，不能只拿去年當唯一基準，應往前看 2–3 年。

### 2. 刪減與凍結完全分開

**刪減**代表預算真的減少。

**凍結**代表經費仍存在，但動支受到條件限制。

不得把「刪 10%＋凍 30%」直接寫成「預算被砍 40%」。

### 3. 提案不等於通過

立委原始提案、黨團提案、委員會討論版本只能用來說明審議過程。

真正的預算結果必須回到三讀、審查總報告、朝野協商結論與最終決議。

### 4. 百分比一定要說分母

「某計畫被刪 80%」與「該機關總預算只少 0.8%」可能同時成立。

所以任何百分比都必須回答：**占誰的多少？**

### 5. 年度總額相同，不代表執行條件相同

1 月就能用 10 億，和 8 月才取得 10 億，不是同一件事。

遇到延遲、追加、凍結／解凍時，必須建立預算時間軸。

### 6. 占比小，不代表影響一定小

如果小科目是其他支出的必要前置，可能形成 **critical dependency**，甚至是 **single point of failure（單點失效）**。

但也不能因為機關說「這筆很關鍵」就直接相信，必須驗證依賴鏈與替代方案。

### 7. 最後才判斷實際影響

不能從「刪了 30%」或「刪了關鍵項目」直接跳到「業務一定停擺」。

應建立：

**科目 → 產出 → 依賴 → 替代方案 → 可用時間 → 歷年執行 → 本年工作量 → 實際結果**

---

## Dependency 怎麼判斷？

Skill 會要求 AI 固定回答四件事：

1. **被刪科目的產出到底是什麼？**
2. **哪些後續工作依賴它？**
3. **有沒有替代方案或其他合法財源？**
4. **沒有它，是否法律上、契約上或技術上真的不能繼續？**

最後將項目分類為：

| 類型 | 意義 |
|---|---|
| 獨立項目 | 刪掉主要只影響自己 |
| 部分依賴 | 會降低其他項目效率或規模 |
| 關鍵前置項目 | 不完成，部分後續工作不能進行 |
| 單點失效項目 | 金額很小，但缺少後可能使整體或核心功能失效 |
| 未能確認 | 現有資料不足以建立依賴關係 |

硬規則是：

> **「只占 5%」不能直接推出「影響只有 5%」；但「這 5% 很關鍵」也不能直接推出「全案一定癱瘓」。兩邊都要證明。**

---

## 影響證據分三級

v1.2 延續 v1.1 的證據分級：

1. **已證實影響**：有決算、採購、服務量、執行率、人力、工程或正式文件證明結果已發生
2. **具體風險**：制度機制、依賴關係或時間壓力存在，但結果尚未有足夠資料
3. **利害關係人主張**：政府、政黨、公務員、廠商、媒體等提出，但尚未獨立驗證

> **「可合理想像的影響」不等於「已證明的影響」。**

## 怎麼使用？

### 方法 A：直接把規範交給 ChatGPT / LLM

把 `SKILL.md` 或完整操作規範上傳到 Project、Workspace、Knowledge、Agent 或其他可長期讀取文件的環境。

然後問：

> 請依照政府預算刪凍查核規範，查核「○○預算被砍 XX%」這個說法。請區分刪減與凍結、確認最終三讀結果，並比較歷年法定預算與實際執行。如果被刪科目可能是其他計畫的必要前置，請執行 Dependency Analysis，確認依賴鏈、替代方案與實際影響。

### 方法 B：每次分析時直接附上 `SKILL.md`

適合沒有長期知識庫或 Skill 機制的 LLM。

### 方法 C：整合進 Agent / MCP / 自動化流程

如果 Agent 具備網路搜尋或政府資料庫查詢能力，可以把 `SKILL.md` 當成固定分析規格。

## 建議提問範例

### 查一則新聞

> 請用這個 Skill 查核：「某部會預算遭刪 90%」是否精確。不要只看新聞，請找最終三讀資料。

### 查「才刪 5%，怎麼可能有影響？」

> 某科目只占整體預算 5%，但機關聲稱刪除後會使整體計畫無法推動。請不要用預算占比直接判斷，請做 Critical Dependency Analysis：確認該科目的具體產出、下游依賴、法律／契約／技術前置條件、替代方案與其他合法財源。

### 查「少了這筆就全部癱瘓」

> 請把「沒有 A 科目就整體不能做」當成待驗證主張。建立 A → B → C 的依賴鏈，逐段找正式證據；若有替代方式，請一併列出。

### 查業務是否真的做不下去

> 請比較歷年實際執行、本年度剩餘法定預算、可用時間、關鍵依賴與工作量，確認「因預算被刪所以服務無法繼續」的因果關係能不能成立。

## 資料來源原則

建議優先順序：

1. 法定預算、三讀資料、審查總報告、正式決議
2. 決算與預算執行資料
3. 法律、正式計畫書、採購文件、契約、技術規格與驗收條件
4. 行政機關官方說明
5. 政黨、立委與政治行為者說明
6. 新聞報導
7. 社群貼文

新聞、政黨、政府新聞稿與政治人物說法都可以是重要線索，但完成正式文件核對以前，應先視為**主張**。

## 適用範圍

目前版本主要以**台灣中央政府與立法院預算審議語境**設計，因此使用「三讀」「凍結」「解凍」「審查總報告」「朝野協商」等用語。

核心方法可延伸到地方政府或其他國家的預算制度，但應依當地法定程序修改資料來源與審議流程。

---

## 這個 Skill 不做什麼？

它不會替你決定：

- 某筆預算「應不應該刪」
- 哪一個政黨比較合理
- 哪一方的政治價值觀比較正確

它先做的是更前面的工作：

> **先把 Amount、Timing、Dependency、Execution 整理完，再判斷政治論述是否成立。**
