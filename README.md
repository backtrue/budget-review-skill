# 政府預算刪凍查核 Skill

**Version 1.1 — Amount × Timing × Execution**

一套給 ChatGPT、Claude、Gemini、Agent 與其他 LLM 使用的政府預算查核規則。

它的目的不是替任何政黨、政府或政治人物辯護，而是要求 AI 在討論「預算被砍」「預算被凍」「某政策做不下去」以前，先把真正的預算事實、可用時間與執行影響整理清楚。

> **不要只問「砍了多少」，要問：相較於什麼、什麼時候能用、刪凍了哪裡、最後為什麼，以及最後真的發生了什麼。**

---

## v1.1 為什麼要加入「時間」？

只比較「去年預算」和「今年預算」仍可能失真。

同樣是年度最後有 10 億元：

- 1 月就確定可用 10 億
- 8 月才完成預算程序後取得 10 億
- 年中追加 3 億才變成 10 億
- 有 3 億先被凍結，後來才解凍

對機關、採購、補助、工程與服務執行來說，完全不是同一件事。

因此 v1.1 把預算分析從單純看 **Amount（金額）**，升級成：

> **Amount × Timing × Execution**

### Amount｜到底有多少錢？

比較法定預算、原編、刪減、凍結、決算與歷年基準。

### Timing｜這些錢什麼時候真的能用？

檢查三讀／公布時點、預算延遲期間的法定執行依據、追加預算、解凍日期、分配／核定時點，以及年度還剩多少執行時間。

### Execution｜最後真的造成什麼影響？

不能只靠「可能很難做事」推論，要繼續找月／季執行率、決標與流標、保留款、服務量、工程時程、補助人數、缺額或離職等資料。

## 為什麼需要這個 Skill？

每逢政府預算審查，新聞與社群常會快速出現這類說法：

- 「某預算被砍 XX 億」
- 「某項預算遭刪 80%」
- 「立委提案刪光某筆預算」
- 「某機關因為預算遭砍，所以業務做不下去」
- 「預算太晚通過，廠商不敢投標、人才開始流失」

這些說法有些可能成立，但都不能只靠一句話證明。

本 Skill 會固定追問：

- 去年法定預算是多少？
- 去年實際執行／決算是多少？
- 去年是否有追加預算、解凍或其他特殊時序？
- 今年原編與三讀後預算是多少？
- 「刪減」與「凍結」各是多少？
- 凍結要怎麼解、何時解？
- 預算什麼時候真正能動支？
- 通過前依什麼法定機制執行？
- 新聞講的是原始提案，還是最後三讀結果？
- 刪凍理由是提案人的理由，還是最後通過的決議文字？
- 所謂「刪 80%」的分母，是整個部會，還是某一個小科目？
- 有沒有採購、執行率、服務量、人事等資料證明所謂的「實際影響」？

## 核心原則

### 1. 建立歷史基準，但不要機械式只比去年

至少比較：

1. 去年法定預算
2. 去年實際執行／決算
3. 今年原編預算
4. 今年三讀後法定預算

但如果去年本身有追加預算、重大解凍、延遲通過、一次性政策或其他異常，就必須再往前看 2–3 年，並拆開年度內時序。

### 2. 刪減與凍結完全分開

**刪減**代表預算真的減少。

**凍結**代表經費仍存在，但動支受到條件限制。

不得把「刪 10%＋凍 30%」寫成「預算被砍 40%」。

### 3. 提案不等於通過

原始提案、黨團提案、委員會討論版本，都只能用來說明審議過程。

最終結果必須回到三讀、審查總報告、協商結論與正式決議。

### 4. 刪凍理由以最後決議為準

不能拿最初提案理由直接代表最後通過理由。

### 5. 百分比一定要說分母

「某計畫被刪 80%」與「該機關總預算只少 0.8%」可能同時成立。

所以任何百分比都必須回答：**占誰的多少？**

### 6. 加入預算時間軸

只要出現延遲通過、追加預算、凍結／解凍、分配延後等情況，就必須整理：

**年度開始 → 通過／公布 → 可動支依據 → 追加／解凍 → 實際取得經費 → 剩餘執行月份**

### 7. 先看刪的是什麼，再看刪多少

人事費、法定義務支出、既有服務、新增政策、一次性採購、工程、宣傳費，即使刪減金額一樣，實際影響也可能完全不同。

### 8. 「合理想像的影響」不等於「已證明的影響」

Skill 將影響分成三層：

| 等級 | 定義 |
|---|---|
| **已證實影響** | 有決算、採購、服務量、執行率、人事等實際資料支持 |
| **具體風險** | 制度機制與時間壓力合理存在，但結果尚未有足夠資料證明 |
| **利害關係人主張** | 政府、政黨、公務員、廠商、工會、媒體或其他人的說法 |

不得把「具體風險」或「主張」直接改寫成「已發生的事實」。

### 9. 最後才判斷實際影響

應建立：

**預算科目 → 可用時間 → 實際業務 → 歷年執行 → 本年工作量 → 採購／人事／服務資料 → 可量化影響**

## 怎麼使用？

### 方法 A：直接把規範交給 ChatGPT / LLM

把 `SKILL.md` 或完整操作規範上傳到 Project、Workspace、Knowledge、Agent 或其他可長期讀取文件的環境。

然後問：

> 請依照政府預算刪凍查核規範，查核「○○預算被砍 XX%」這個說法。請區分刪減與凍結、確認最終三讀結果，並比較歷年預算、實際執行與年度內可動支時間軸。

### 方法 B：每次分析時直接附上 `SKILL.md`

適合沒有長期知識庫或 Skill 機制的 LLM。

### 方法 C：整合進自己的 Agent / MCP / 自動化流程

若 Agent 能搜尋政府資料、採購資料或執行報告，可把本 Skill 當固定查核規格。

## 建議提問範例

### 查一則「被砍 XX%」的新聞

> 請用這個 Skill 查核這則新聞。不要只看新聞，請找最終三讀資料，區分刪減與凍結，並確認百分比的分母。

### 查「今年不能只跟去年比」

> 請檢查去年是否有追加預算、解凍、延遲通過或一次性支出。如果去年不是正常基準，請改看前 2–3 年並建立年度內時間軸。

### 查「預算太晚所以做不了事」

> 請先確認預算何時通過、通過前依何種法定機制執行、何時實際可動支，再查每月／每季執行率、採購與保留資料，判斷影響是已證實、具體風險，還是目前只有主張。

### 查「廠商不敢投標」

> 不要直接接受這個因果關係。請查投標家數、流標率、決標時點、採購案數量與可比較期間，確認是否真的出現異常。

### 查「人才流失」

> 請找缺額率、離職率、招聘、約聘續約或人力異動資料。沒有資料時，只能列為主張或具體風險，不得寫成已證實結果。

## 資料來源原則

優先順序通常為：

1. 法律、法定預算、三讀資料、審查總報告、正式決議
2. 決算、分配預算、預算執行報告、政府採購與業務統計
3. 行政機關官方說明
4. 政黨、立委、公務員、廠商或其他利害關係人說明
5. 新聞報導
6. 社群貼文

低順位來源可以提供線索與影響主張，但不能覆蓋高順位正式資料。

## 適用範圍

目前版本主要以**台灣中央政府與立法院預算審議語境**設計。

如果預算未在年度開始前完成，模型應查明當年度實際適用的法律依據與執行規則，而不是自己假設「照去年預算花」。核心方法也可延伸到地方政府或其他國家，但必須改用當地制度。

---

## 這個 Skill 不做什麼？

它不會替你決定：

- 某筆預算應不應該刪
- 哪一個政黨比較合理
- 哪一方的政治價值觀比較正確
- 某個「聽起來合理」的後果就一定真的發生

它要求的是：

> **先把金額、時間與執行證據整理完，再判斷政治論述是否成立。**
